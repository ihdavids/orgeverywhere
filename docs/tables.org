#+DOC_SECTION: Tables

* Tables in a plain text file
  An org table is a block of lines that start with =|=. OrgEverywhere keeps
  it aligned as you type, lets you move rows and columns around and runs
  formulas over it, so a table can be a small spreadsheet that lives in
  your notes.

  [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/table_formulas.gif]]

  Emacs evaluates table formulas with calc and emacs lisp. OrgEverywhere
  has its own formula language instead: the cell reference syntax of org
  (=@2$3=, =$1..$3=, =@>=) on top of python style expressions, with a set
  of spreadsheet functions. Most simple org formulas work unchanged;
  calc specific functions and lisp formulas (='(...)=) do not.

  The editing half (alignment, moving cells, inserting rows and columns)
  comes from the [[https://packagecontrol.io/packages/Table%20Editor][Table Editor]] package, which OrgEverywhere installs and
  turns on for org files (=enable_table_editor=, =table_editor_syntax=).

  Tables are part of the file you are editing: everything here works on
  the buffer, with or without the orgs server. Only references to tables
  in *other* files (remote references by id, random rows from any table)
  ask the server where those tables are.

* Creating a table
  Type a =|=, some text and press =tab=: the line becomes a table row and
  the cursor moves to the next cell. Type =|-= on the next line and press
  =tab= to turn it into a separator (hline).

  [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/table_basic_creation.gif]]

  #+BEGIN_SRC org
    | Name  | Qty | Price |
    |-------+-----+-------|
    | Apple |   3 |  0.50 |
    | Pear  |   2 |  0.75 |
  #+END_SRC

  Other ways to get a table:

  - *Org Insert Blank Table* (=org_insert_blank_table=) asks for the size
    as =WxH= (=4x3=) and inserts an empty table with a header separator.

    [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/blank_table_insert.gif]]

  - *Org Convert Region To Table* (=org_convert_selection_to_table=) turns
    the selected text into a table. The separator is guessed from the
    text: comma, semicolon, tab or space, whichever splits the lines most
    evenly (comma wins a tie). A python style list of lists
    (=[[1,2],[3,4]]=) is understood too.

    [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/convert_region_to_table.gif]]

  - *Org Import Csv* (=org_import_table_from_csv=) asks for a file and
    inserts its contents as a table at the cursor, with the same separator
    guessing.

* Editing a table
  =tab= and =shift+tab= move between cells and realign the table, =enter=
  moves down a row. The rest of the editing keys:

  | Keys                | Does                                            |
  |---------------------+-------------------------------------------------|
  | =tab= / =shift+tab= | next / previous cell (and align)                |
  | =enter=             | next row                                        |
  | =shift+enter=       | split the cell: the text after the cursor moves down |
  | =alt+shift+right=   | insert a column                                 |
  | =alt+shift+left=    | delete the column                               |
  | =alt+shift+down=    | insert a row                                    |
  | =alt+shift+up=      | delete the row                                  |
  | =alt+right= / =alt+left= | move the column right / left               |
  | =alt+up= / =alt+down=    | move the row up / down                     |
  | =alt+o t a=         | align the table                                 |
  | =alt+o t -=         | insert a separator line                         |
  | ~alt+o t =~         | insert a double separator line                  |
  | =alt+o enter=       | separator below, and move past it               |
  | =alt+o t j=         | join the current line with the next             |

  With NeoVintageous the same commands sit under =space= in command mode
  (=space t a=, =space t -=, =space t e= ...).

  [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/table_add_delete_cells.gif]]

  [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/table_moving_cells_around.gif]]

  Moving or inserting rows and columns also updates the formulas below the
  table, so a formula that read =$3= reads the column's new number. A
  formula that pointed at a deleted row or column is marked =@INVALID= or
  =$INVALID= so you can see it needs fixing.

  *Org Clear Table Cell* (=org_clear_cell=, =space t k=) empties the cell
  under the cursor.

  [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/clear_cell.gif]]

* Formulas
** Writing a formula
   Formulas live on a =#+TBLFM:= line directly under the table. Each
   formula has a target and an expression; several formulas share the line,
   separated by =::=.

   #+BEGIN_SRC org
     | Name  | Qty | Price | Total |
     |-------+-----+-------+-------|
     | Apple |   3 |  0.50 |   1.5 |
     | Pear  |   2 |  0.75 |   1.5 |
     |-------+-----+-------+-------|
     | Sum   |   5 |       |   3.0 |
     #+TBLFM:$4=$2*$3::@>$2=vsum(@2..@-1)::@>$4=vsum(@2..@-1)
   #+END_SRC

   You do not have to edit the =#+TBLFM:= line by hand. Type the formula
   into a cell and evaluate the table: OrgEverywhere moves it to the
   =#+TBLFM:= line, with a target made from the cell you typed it in.

   | You type          | It becomes          | Applies to       |
   |-------------------+---------------------+------------------|
   | ~=$2*$3~          | ~$4=$2*$3~          | the whole column |
   | ~:=$2*$3~         | ~@3$4=$2*$3~        | this cell only   |
   | ~>=vsum($2..$4)~  | ~@3=vsum($2..$4)~   | the whole row    |

   [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/table_formulas_insert.gif]]

   If the cell already has a formula, the new one replaces it.

** Evaluating
   - =alt+o c c= (=org_recalc=, =space c c= with NeoVintageous) in a table
     evaluates every formula of that table. =org_recalc= is the do what I
     mean key: on a source block it runs the block, on a dynamic block it
     refreshes the block, in a table it recalculates.
   - *Org Eval Cell* (=org_fill_in_formula_from_cell=) does the same from a
     cell, after moving a formula typed into the cell to =#+TBLFM:=.
   - *Org Execute Formula* (=org_execute_formula=) evaluates only the
     formula of the cell under the cursor.
   - *Org Execute All Tables* (=org_execute_all_tables=) recalculates every
     table in the file, top to bottom.

   A formula that fails writes =<ERR>= into its cells; the python console
   (=ctrl+`=) has the details.

** Seeing what a formula touches
   When the cursor is in a cell that a formula writes, the cells the
   formula reads are outlined, and so is the formula on the =#+TBLFM:=
   line. With the cursor on a formula in the =#+TBLFM:= line, the same
   happens for that formula.

   - *Org Show Table Rows* / *Org Hide Table Rows* put the row and column
     numbers next to the table, which helps when writing references.
     Separator lines are numbered with roman numerals.

     [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/table_show_table_rows.gif.gif]]

   - *Org Highlight Formula* (=org_highlight_formula=) highlights the
     formula under the cursor; *Org Clear Table Highlights*
     (=org_clear_table_regions=) removes the outlines.
   - =tableShowCursor= (default true) outlines the cell under the cursor.
     A =NoTableHighlight= property on the heading turns the outlines off
     for its tables.

** Changing a formula
   *Org Edit Table Formula* (=org_edit_formula_for_cell=, =space t e=)
   copies the formula of the current cell back into the cell. Edit it and
   evaluate the table again.

   [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/edit_formula.gif]]

   Note that the copy carries its full target (~$4=$2*$3~). Put the
   leading marker back (~=~, ~:=~, ~>=~) to say how the formula should be
   stored, or edit the =#+TBLFM:= line directly.

** A one off formula over a column
   *Org Table Exec Below* (=org_exec_on_column=) asks for an expression and
   applies it once to the current cell and every cell below it in the
   column. Nothing is stored. Useful for nudging a column of numbers:
   =$0*1.1=.

   [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/edit_by_formula.gif]]

* The formula language
** References
   Rows and columns are numbered from 1. Separator lines are not counted:
   in the table above, =@1= is the header row and =@2= is "Apple".

   | Reference     | Means                                                 |
   |---------------+-------------------------------------------------------|
   | =@2$3=        | row 2, column 3                                       |
   | =$3=          | column 3 of the row being computed                    |
   | =@2=          | row 2 of the column being computed                    |
   | =$-1=, =$+2=  | one column left, two columns right of the current one |
   | =@-1=, =@+1=  | the row above, the row below                          |
   | =@-1$-2=      | relative row and column together                      |
   | =@<=, =@<<=   | the first row, the second row                         |
   | =@>=, =@>>=   | the last row, the last but one                        |
   | =$<=, =$>=    | the first column, the last column                     |
   | =@#=, =$#=    | the number of the current row, of the current column  |
   | =$1..$3=      | columns 1 to 3 of the current row (a range)           |
   | =@2..@-1=     | rows 2 to the one above, in the current column        |
   | =@2$1..@4$3=  | the block of cells between the two corners            |

   Org's =@I= / =@II= references to separator lines are not supported.

** Targets
   The part before the ~=~ says which cells the formula fills.

   | Target          | Fills                                              |
   |-----------------+----------------------------------------------------|
   | ~$4=~           | column 4, every row below the first separator      |
   | ~@3=~           | row 3, every column                                |
   | ~@3$4=~         | one cell                                           |
   | ~@>$2=~         | the last row, column 2                             |
   | ~@2$1..@5$2=~   | every cell of the block                            |
   | ~$name=~        | a named column (see Advanced tables)               |

   A column formula skips the rows above the first separator, so headers
   are safe. A single cell formula wins over a column or row formula that
   covers the same cell.

** Expressions
   Expressions are python expressions evaluated in a sandbox: =+ - * /=,
   =%= (modulo), =**= (power), comparisons (~==~ ~!=~ ~<~ ~>~ ~<=~ ~>=~),
   =and=, =or=, =not=, strings in quotes and the conditional form:

   #+BEGIN_EXAMPLE
     $4=$2*$3 if $3 > 0 else 0
     $5="late" if date($4) < now() else ""
   #+END_EXAMPLE

   A cell's text becomes a value when it is used: =12= and =1.5= are
   numbers, =40%= is =0.4=, =true=, =t= and =false= are booleans, anything
   else is a string. Dates and durations need =date()= and =duration()=.

** Format flags
   A formula can end in =;flags=:

   - =N= - empty cells count as =0= (normally an empty cell is an empty
     string, and adding it to a number fails).
   - =%.2f= - print floating point results with that many decimals.

   #+BEGIN_SRC org
     | a     | b     | c   |
     | 1     | 1     |     |
     | 0.476 | 0.476 | 0.0 |
     #+TBLFM:@3=@2/2.1;N%.3f
   #+END_SRC

   The rest of calc's mode flags have no meaning here and are ignored.

** Constants and properties
   =#+CONSTANTS:= defines names for numbers, used with a =$= in front:

   #+BEGIN_SRC org
     #+CONSTANTS: c=299792458 g=9.81
     | mass | energy |
     |------+--------|
     |    2 |        |
     #+TBLFM:$2=$1*$c**2
   #+END_SRC

   The properties of the heading the table sits under are available the
   same way, prefixed with =PROP_=: a heading with =:Rate: 85= in its
   property drawer can use =$PROP_Rate= in its tables.

   Built in symbols are used without a =$=: =pi=, =True=/=true=/=t=,
   =False=/=false=, =None=/=nil=.

** Functions
   | Function                    | Does                                                        |
   |-----------------------------+-------------------------------------------------------------|
   | =vsum(range)=               | sum of the cells                                            |
   | =vmean(range)=              | average                                                     |
   | =vmedian(range)=            | median                                                      |
   | =vmax(range)=, =vmin(range)= | largest, smallest                                          |
   | =vsumifeq(a,b,range)=       | sum of the cells of range on rows where ~a == b~            |
   | =vsumifgt=, =vsumiflt=, =vsumifgteq=, =vsumiflteq= | the same with ~>~, ~<~, ~>=~, ~<=~   |
   | =abs=, =int=, =float=, =bool=, =str= | conversions                                        |
   | =round=, =floor=, =ceil=, =trunc= | rounding                                              |
   | =sqrt=, =pow(x,y)=, =exp=, =log=, =log10=, =log2= | math                                  |
   | =sin=, =cos=, =tan=, =asin=, =acos=, =atan= | trigonometry (radians)                      |
   | =sinh=, =cosh=, =tanh=, =asinh=, =acosh=, =atanh= | hyperbolic functions                  |
   | =degrees=, =radians=        | convert angles                                              |
   | =rand()=, =randomf()=       | random number from 0 to 1                                   |
   | =random(a,b)=, =randint(n)= | random integer from a to b, below n                         |
   | =now()=                     | the current date and time                                   |
   | =date(x)=                   | an org timestamp from a cell or string                      |
   | =duration(x)=               | a duration (=3d=, =2h=, =1:30=); add it to a date           |
   | =year=, =month=, =day=, =hour=, =minute=, =second= | parts of a date                      |
   | =weekday(d)=, =yearday(d)=  | day of the week (monday is 0), day of the year              |
   | =time(d)=                   | the time of day of a date                                   |
   | =filename(x)=               | a file link or relative path made absolute                  |
   | =remote(name,@r$c)=         | a cell of another table (see below)                         |
   | =sbe(name, x=1)=            | the result of a named source block (see Source Blocks)      |
   | =highlight(cell,color,text)= | colour a cell, return text                                 |
   | =red(cell)=, =green=, =blue=, =yellow=, =cyan=, =purple=, =pink= | colour the cell, keep its value |
   | =gradient(cell,pct,c1,c2,...)= | colour by a 0 to 100 value through a list of colours     |
   | =passed(test)=              | a green =PASSED= or a red =FAILED= (used by the table tests) |

   Dates and durations work together: =date($3)+duration($2)= is the
   timestamp =$2= after =$3=.

   #+BEGIN_SRC org
     | Task   | Effort | Start            | End              |
     |--------+--------+------------------+------------------|
     | Design | 2d     | <2021-03-15 Mon> | <2021-03-17 Wed> |
     | Build  | 4d     | <2021-03-17 Wed> | <2021-03-21 Sun> |
     #+TBLFM:$4=date($3)+duration($2)
   #+END_SRC

   *Org Show Table Tests* opens the table unit tests: a file of small
   tables exercising every function, a good place to see a function used.

   [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/tables_unit_tests.gif]]

** Remote references
   =remote(name, @r$c)= reads a cell of another table. =name= is either

   - the =#+NAME:= of a table in the same file, or
   - the =ID= or =CUSTOM_ID= of a heading anywhere in your org files: the
     first table under that heading is used.

   #+BEGIN_SRC org
     #+NAME: rates
     | role | rate |
     |------+------|
     | dev  |   85 |
     | qa   |   60 |

     | hours | cost |
     |-------+------|
     |    10 |  850 |
     #+TBLFM:$2=$1*remote('rates',@2$2)
   #+END_SRC

   Since 2.0 an id is looked up through the orgs server, so a remote table
   can be in any file the server knows, open or not (an open buffer is
   used as is, unsaved changes included). The answer is remembered until
   the server reports a change, so recalculating a big table does not ask
   for the same id again and again. Without a server only ids in open
   buffers are found. A reference that cannot be resolved gives
   =<UNK REF>=.

* Advanced tables
  Org's advanced table syntax is supported. Put a marker in the first
  column of a row. Once a table uses markers, column formulas and row
  ranges leave the marker column alone; columns keep their numbers, so
  the first data column is still =$2=.

  | Marker  | Row is                                                              |
  |---------+---------------------------------------------------------------------|
  | =!=     | column names: =$a= refers to the column named =a=                   |
  | =^=     | names for the cells in the row above                                |
  | =_=     | names for the cells in the row below                                |
  | =$=     | parameters: ~max=5~ defines =$max= for the formulas                 |
  | =#=     | recalculated as you move through it with =tab= / =enter=            |
  | =*=     | recalculated with the table, not on the fly                         |
  | =/=     | skipped by formulas                                                 |

  #+BEGIN_SRC org
    |   | results |    |   |   |   |
    |---+---------+----+---+---+---|
    | ! | a       | b  | c | d | e |
    | # | 9       |    |   | 4 | 5 |
    | # | 3       | 1  | 2 |   |   |
    | $ | max=5   |    |   |   |   |
    | # | 15      | 10 |   |   |   |
    #+TBLFM:@4$2=$b+$c::@3$2=$e+$d::@6$2=$max+$b
  #+END_SRC

  See [[https://orgmode.org/manual/Advanced-features.html][Advanced features]] in the org manual.

* Your own functions and symbols
  Python files in =Packages/User/orgtable/= can add functions and
  symbols to the formula language. Turn the folder on first:

  #+BEGIN_SRC js
    "enableTableExtensions": true,
  #+END_SRC

  - *A function*: the file name is the function name, the file defines
    =Execute=. =Packages/User/orgtable/stamp.py= gives =stamp()=:

    #+BEGIN_SRC python
      import datetime

      def Execute():
          return str(datetime.datetime.now())
    #+END_SRC

    Arguments are passed as written in the formula. A cell reference
    arrives as a cell object: =str(cell)= is its text.

  - *Symbols*: a file with =AddSymbols(s)= adds names to the dictionary it
    is given. Symbols are used without a =$=:

    #+BEGIN_SRC python
      def AddSymbols(s):
          s['c'] = 299792458
    #+END_SRC

  Extensions are loaded once. While writing one set
  =forceLoadExternalExtensions= to true so each evaluation reloads them
  (and turn it off again: it is slow).

* Plotting with gnuplot
  *Org Plot Table* (=org_plot_table=) draws a table with
  [[http://www.gnuplot.info/][gnuplot]] and puts a link to the picture under the table.

  1. Install gnuplot and tell OrgEverywhere where it is:

     #+BEGIN_SRC js
       "gnuplot": "/usr/local/bin/gnuplot",
     #+END_SRC

  2. Describe the plot with a =#+PLOT:= line above the table.
  3. Run *Org Plot Table* with the cursor in the table (or on the
     =#+PLOT:= line).

  #+BEGIN_SRC org
    #+PLOT: title:"Citations" ind:1 deps:(3 4) with:lines set:grid file:plot.png
    |    Sede   |  Max   | H-index |  top  |
    |-----------+--------+---------+-------|
    | Sao Paolo |  71.00 |   11.50 |  13.5 |
    | Stockholm | 134.19 |   14.33 | 16.33 |
    | Leeds     | 165.77 |   19.68 | 21.68 |
    | Morelia   | 257.56 |   17.67 | 19.67 |
    | Chile     | 257.72 |   21.39 | 23.39 |
    #+TBLFM:$4=$3+2.0
  #+END_SRC

  [[https://raw.githubusercontent.com/ihdavids/orgextended_docs/master/images/tables_gnuplot.gif]]

  | Option          | Meaning                                                       |
  |-----------------+---------------------------------------------------------------|
  | =title:"..."=   | the plot title (default "Table Data")                         |
  | =ind:N=         | the column used as the x axis                                 |
  | =deps:(a b)=    | the columns plotted against it (default: all)                 |
  | =with:STYLE=    | gnuplot style: =lines=, =points=, =histograms=, =candlesticks= ... |
  | =set:"..."=     | a gnuplot =set= command; repeat for more                      |
  | =unset:"..."=   | a gnuplot =unset= command                                     |
  | =using:"..."=   | a gnuplot =using= clause, written as is                       |
  | =include:header= | plot the rows above the first separator too                  |
  | =file:NAME=     | the output; the extension picks the terminal (png, jpg, gif, svg, ps, html, txt). =file:viewer= opens gnuplot's own window instead |

  Without =file:= the picture is =plot_<date>_<time>.png= beside the org
  file. The link goes into a =#+RESULTS:= under the table and the images
  in the file are shown inline.

  The =#+PLOT:= line is read from the heading the table sits under: one
  plot description per heading.

  A gnuplot source block is the other way to plot: see Diagrams.

* Random rows
  *Org Insert Rnd Table Row* (=org_insert_random_row_from_table=) picks a
  named table and inserts one of its rows, chosen at random, at the
  cursor: a quick way to keep a list of writing prompts, meals or names.
  Header rows, separators and advanced table marker rows are never
  picked.

  With the orgs server connected the list offers every =#+NAME:= table the
  server knows (plus the ones in this file) and the table can live in any
  file. Without it only the tables named in this file are offered. A
  key binding of your own can name the table directly with the =tblName=
  argument:

  #+BEGIN_SRC js
    { "keys": ["ctrl+alt+r"], "command": "org_insert_random_row_from_table",
      "args": { "tblName": "meals" } }
  #+END_SRC

* Tables as data
  A named table can be the input of a source block (=:var data=name=),
  and a source block's output can be a table (=:results table=). See
  Babel. That makes it easy to turn a table into any other format: a
  python block that prints csv, for instance.

  #+BEGIN_EXAMPLE
    #+BEGIN_SRC python :var DATA=prices :results raw
      for r in DATA:
          print(",".join([str(x) for x in r]))
    #+END_SRC
  #+END_EXAMPLE
